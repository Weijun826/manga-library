# 漫畫收藏管理 Windows 應用程式設計規格

## 1. 文件狀態

- 日期：2026-08-13
- 狀態：設計已依使用者「都以你建議的為主」的授權收斂，可供實作計畫使用
- 目標使用者：目前這台 Windows 電腦的單一使用者
- 目前藏書規模：100 本以內
- 產品類型：實體漫畫收藏管理器
- 工作名稱：漫畫書庫；正式發布名稱可在不改變資料與產品邊界的前提下另行命名

若使用者後續提出不同需求，以最新明確指示為準並修訂本文件。

## 2. 產品結論

本產品用來管理實體漫畫作品、出版版本與單冊收藏。它優先回答三個問題：

1. 我擁有哪些漫畫？
2. 一套作品還缺哪些冊？
3. 下一本想買什麼？

閱讀狀態是單冊的輕量附加資訊，不是產品主軸。產品不是漫畫閱讀器、下載器、一般書籍閱讀習慣工具或線上社群。

## 3. 已確認的產品決策

- 收藏管理優先，閱讀追蹤次要。
- 初版只支援 Windows 桌面。
- 資料保存在本機，不需要登入、帳號、雲端同步或手機版。
- 技術棧沿用 Tauri 2、React、TypeScript、Vite、Rust 與 SQLite。
- 從官方 `create-tauri-app` 的 `react-ts` 範本建立乾淨專案，不複製舊書庫介面。
- 可選擇性移植舊書庫已驗證的 SQLite migration、備份、ISBN 校驗、封面快取與 Windows 安裝做法。
- 首次建庫使用作品搜尋與批次勾選；日常新增使用 ISBN；兩者都保留手動修正及手動新增。
- 每冊可選填購入價格、購入日期、書況、存放位置與備註。
- 初版以一套完整主題為主，不同時製作深色模式或主題商店。

## 4. 初版範圍

### 4.1 包含

- 收藏總覽
- 系列式漫畫書庫
- 作品、出版版本與單冊資料
- 擁有、已讀、想買與衍生缺卷狀態
- 搜尋、篩選與排序
- 作品搜尋後批次建立卷數
- ISBN 查找與重複 ISBN 防護
- 完整手動新增及修正
- 本機封面快取與自訂封面
- 本機 SQLite 保存
- 備份、匯出與還原
- 標準 Windows 安裝與解除安裝

### 4.2 不包含

- 手機、macOS、Linux 或瀏覽器版本
- 帳號、登入、社交、分享或跨裝置同步
- 電子漫畫閱讀、CBZ／PDF 閱讀或漫畫下載
- 頁碼、閱讀計時、連續天數、提醒、徽章或排行榜
- 借出管理、簽名、特典、首刷附件或多本相同副本的完整追蹤
- 價格走勢、購物網站比價或自動購買
- 付款、訂閱或授權服務
- 未獲授權的出版社網站批次爬取

## 5. 產品資訊架構

主要導覽固定為四個區域。

### 5.1 收藏總覽

- 顯示系列數、實體冊數、已讀冊數與缺少冊數。
- 顯示最近新增的漫畫。
- 顯示正在收集但尚未補齊的系列。
- 不使用大量統計卡片、複雜圖表或遊戲化成就。

### 5.2 我的書庫

- 以作品系列為主要卡片，不把每冊平鋪成彼此無關的書籍。
- 支援書名、原文名、作者及出版社搜尋。
- 支援連載狀態、收藏完成度及閱讀完成度篩選。
- 點入系列後查看出版版本與卷數格狀清單。

### 5.3 待補清單

- 顯示已知但尚未擁有的實體冊別。
- 「缺少」由已知冊別減去已擁有冊別即時計算，不另存可矛盾的狀態。
- 可將特定冊別加入想買清單。
- 購買後可一鍵標記為已擁有，並選填收藏資料。

### 5.4 設定

- 備份狀態與手動匯出。
- 備份還原。
- 封面快取管理。
- 應用程式版本資訊。

新增漫畫是全域主要動作，不占用一個永久導覽區域。

## 6. 核心流程

### 6.1 首次建立收藏

1. 搜尋作品名稱。
2. 選擇或建立作品。
3. 選擇台灣中文版、日文版、完全版或其他出版版本。
4. 取得已知冊別；資料不足時由使用者輸入總冊數或新增冊別。
5. 批次勾選已擁有冊別。
6. 選擇性批次勾選已讀冊別。
7. 確認後以單一 SQLite transaction 保存。

### 6.2 日常以 ISBN 新增

1. 輸入 ISBN；鍵盤與一般 USB 條碼掃描器都視為文字輸入。
2. 在本機完成 ISBN-10／ISBN-13 格式及校驗碼驗證。
3. 檢查是否已有相同 ISBN。
4. 查本機快取，再依序查 Google Books 與 Open Library。
5. 將結果正規化為內部候選資料。
6. 使用者確認作品、出版版本、卷號與封面。
7. 選填購入價格、日期、書況、位置及備註。
8. 保存收藏並快取封面。

### 6.3 查找失敗

- 保留已輸入 ISBN。
- 說明是格式錯誤、沒有結果、離線、限流或服務錯誤。
- 提供重試與手動新增。
- 手動新增與自動新增保存相同的完整資料結構。

## 7. 資料模型

所有主要資料表使用不可變 UUID 主鍵，日期時間以 UTC ISO 8601 保存，介面依本機時區顯示。SQLite foreign keys 必須啟用，schema 透過版本化 migration 更新。

### 7.1 `series`

表示抽象作品，不綁定單一地區出版社。

- `id`
- `title`
- `original_title`，可空
- `description`，可空，保存為純文字
- `publication_status`：`ongoing`、`completed`、`hiatus`、`unknown`
- `representative_cover_asset_id`，可空
- `created_at`
- `updated_at`

作者、原作、作畫與譯者不塞入單一字串欄位；使用 `contributors` 與關聯表保存姓名及角色。

### 7.2 `contributors` 與 `series_contributors`

- `contributors`：`id`、`display_name`
- `series_contributors`：`series_id`、`contributor_id`、`role`、`sort_order`
- `role` 初版支援 `author`、`story`、`art`；譯者屬於特定出版版本或單冊，不放在作品層。

### 7.3 `editions`

表示作品的特定地區與出版形態。

- `id`
- `series_id`
- `name`，例如「台灣中文版」或「完全版」
- `language_code`
- `region_code`
- `publisher`
- `format`：`tankobon`、`omnibus`、`deluxe`、`box_set`、`other`
- `release_status`：`ongoing`、`completed`、`hiatus`、`unknown`
- `known_volume_count`，可空，只作摘要，不取代實際 `volumes` 資料
- `created_at`
- `updated_at`

同一作品可有多個版本，普通版與完全版的卷數不得混合。

### 7.4 `volumes`

表示可實際持有的一冊或一個套裝項目。

- `id`
- `edition_id`
- `display_label`，例如 `1`、`1.5`、`上`、`下`、`全一冊`
- `sort_key`，以固定格式文字保存自然排序鍵
- `title_override`，可空
- `isbn_10`，可空且唯一
- `isbn_13`，可空且唯一
- `translator`，可空
- `availability_status`：`released`、`upcoming`、`unknown`
- `release_date`，可空，允許只保存年或年月並搭配精度欄位
- `release_date_precision`：`day`、`month`、`year`、`unknown`
- `list_price_amount`，可空，以整數最小貨幣單位保存
- `list_price_currency`，可空，使用 ISO 4217 代碼
- `cover_asset_id`，可空
- `metadata_source`：`manual`、`google_books`、`open_library`、`ncl_import` 或其他已註冊來源
- `created_at`
- `updated_at`

`edition_id + sort_key + display_label` 建立唯一約束。ISBN 正規化後才比較及保存。

部分日期使用可排序的正規形式保存：只有年份時存為該年 `01-01` 並標記 `year`；只有年月時存為該月 `01` 日並標記 `month`。介面必須依精度顯示，不得把補入的月日誤呈現為真實出版日期。

### 7.5 `collection_items`

表示使用者對單冊的收藏狀態；每個 `volume_id` 最多一筆。

- `id`
- `volume_id`，唯一
- `is_owned`
- `is_read`
- `is_wishlisted`
- `purchase_price_amount`，可空，以整數最小貨幣單位保存
- `purchase_price_currency`，可空
- `acquired_on`，可空，保存本機日期
- `condition`：`new`、`like_new`、`good`、`fair`、`poor`、`unknown`
- `storage_location`，可空，自由文字
- `notes`，可空，純文字
- `created_at`
- `updated_at`

狀態規則：

- `is_read = true` 不代表 `is_owned = true`；使用者可能讀過借來的書。
- `is_owned = true` 時自動取消 `is_wishlisted`，避免同冊同時顯示想買與擁有。
- 取消擁有不自動清除已讀狀態。
- 缺少冊別是存在於 `volumes`、`availability_status = released` 且尚未擁有的冊別。`upcoming` 顯示為即將出版，`unknown` 不計入缺少；不得只因出版日期空白就推定已發行。

### 7.6 `cover_assets`

- `id`
- `source_type`：`remote_cache`、`user_file`、`generated`
- `source_url`，可空
- `relative_path`
- `mime_type`
- `byte_size`
- `sha256`
- `created_at`

封面以內容 hash 去重。資料庫只保存相對路徑，不保存任意外部絕對路徑。

### 7.7 `metadata_cache`

- 正規化查詢鍵、來源、回應摘要、擷取時間與過期時間。
- 不把未清理的遠端 HTML 直接寫入產品欄位。
- 快取失效不影響既有收藏資料。

### 7.8 `metadata_provenance`

- `entity_type`、`entity_id`、`field_name`
- `source`、`external_id`、`retrieved_at`
- 只記錄由外部來源帶入的欄位；使用者修改欄位後將該欄位來源更新為 `manual`。
- provenance 用於診斷與重新查找，不用來阻止使用者覆寫資料。

## 8. 查找服務架構

所有提供者實作相同介面：

```ts
interface MangaMetadataProvider {
  lookupByIsbn(isbn: string): Promise<MetadataCandidate[]>;
  searchSeries(query: string): Promise<MetadataCandidate[]>;
}
```

`MetadataCandidate` 包含正規化欄位、欄位來源及可顯示的警告。提供者失敗不直接拋到畫面，而是轉成可辨識的 `invalid_input`、`not_found`、`offline`、`rate_limited`、`provider_error`。

Google Books 與 Open Library 主要回傳單冊書目，不保證提供可靠系列結構。作品搜尋會把候選單冊整理成可供確認的群組，但不得只靠相似書名自動合併。自動群組至少需要正規化系列名，並參考作者、出版社、語言與版本；證據不足時保留為分開候選，由使用者選擇既有系列或建立新系列。

初版提供者順序：

1. 本機快取
2. Google Books
3. Open Library

國家圖書館資料先保留 `ncl_import` 邊界，不列為初版必要提供者。已分析的 2025 年 6 月官方資料包含 5,282 筆，其中 934 筆上架分類為漫畫書；漫畫資料同時包含 624 筆數位平台電子書與 310 筆圖書，因此未來匯入必須區分實體與電子出版物。單月檔案不是完整歷史索引。

不得在未確認授權、速率限制與穩定性前把出版社網站爬取加入正式產品。

## 9. 程式架構

### 9.1 React 介面層

- 頁面、表單、鍵盤操作、搜尋、篩選及保存狀態。
- 只透過服務介面取得資料，不直接寫 SQL 或假設 Windows 路徑。

### 9.2 漫畫領域層

- 系列、版本、冊別與收藏狀態規則。
- ISBN 正規化及驗證。
- 特殊卷號排序、缺卷與完成度計算。
- 不依賴 React、Tauri 或網路，能以單元測試驗證。

### 9.3 資料與服務層

- SQLite repositories 與 transaction 邊界。
- metadata providers 與正規化。
- 封面快取及備份協調。

### 9.4 Tauri／Rust 系統層

- 應用程式資料目錄與安全檔案操作。
- 備份快照、匯出及還原。
- Windows 單一執行個體、視窗狀態與安裝設定。
- 不承擔漫畫領域規則。

## 10. 視覺與互動設計

視覺方向是「現代日本編輯部 × 私人漫畫收藏櫃」。介面保持中性克制，讓不同作品的封面成為主角。

### 10.1 色彩與排版

- 微暖紙白主背景。
- 深石墨黑側邊導覽。
- 接近黑色的主要文字。
- 克制朱紅色作主要動作及重要狀態。
- 不使用漫畫對話框、速度線、網點或大量二次元裝飾。
- 狀態同時以圖示、文字或形狀表達，不只依賴顏色。
- 初版使用 Windows 系統繁體中文字型堆疊；若日後內嵌字型，先確認散布授權。

### 10.2 書庫與系列詳情

- 書庫使用可自動調整欄數的系列封面格狀排列。
- 系列卡片只顯示封面、系列名、已擁有冊數及進度。
- 系列詳情頂部顯示作品及版本切換，下方顯示冊別封面格。
- 已擁有冊別使用完整封面；未擁有冊別降低彩度。
- 已讀及想買使用小型但清楚的標記。
- 點擊單冊才顯示購入及收藏細節。
- 批次模式由明確動作進入，不常駐大量複選框。

### 10.3 缺封面與載入狀態

- 缺封面時產生風格一致的文字封面。
- 不顯示破圖、未處理的空白框或遠端錯誤圖示。
- 封面載入前保留正確比例，避免版面跳動。

### 10.4 Windows 互動

- 初版使用系統標題列。
- 建議初始視窗約 1280 × 820，最低約 1040 × 700。
- `Ctrl+K` 聚焦全域搜尋。
- `Ctrl+N` 開啟新增漫畫。
- `Esc` 關閉對話框或退出批次模式。
- 所有核心滑鼠操作都提供鍵盤路徑。
- 支援 Windows 減少動態效果偏好。
- 一般轉場約 140–180 毫秒，以 `transform` 與 `opacity` 為主。

## 11. 保存、備份與還原

- 一般資料修改在 SQLite transaction 成功後才顯示已保存。
- 批次標記必須全部成功或全部回滾。
- 每次啟動前不強制備份；在 schema migration 與還原前一定建立安全備份。
- 自動備份在資料有變更且距上次成功備份至少 24 小時後建立，保留最近 7 份。
- 手動匯出格式為版本化 ZIP，副檔名使用 `.mangashelf-backup`。
- 匯出包包含 manifest、SQLite 一致快照及必要封面資產。
- 還原前驗證 manifest、格式版本、檔案 hash 與資料庫完整性。
- 還原前建立一份可辨識的還原前備份；還原失敗時保留目前資料。

## 12. 錯誤處理

- 無效 ISBN：在本機指出格式錯誤，不發網路請求。
- 重複 ISBN：開啟既有項目，不建立副本。
- 無結果：保留輸入並提供手動新增。
- 離線：顯示離線狀態，允許重試或手動保存。
- API 限流：顯示服務暫時受限並嘗試下一提供者。
- 多來源衝突：顯示候選資料，由使用者確認。
- 封面失敗：使用文字封面，不阻止保存。
- SQLite 失敗：保留未保存表單，不顯示成功。
- 批次失敗：整筆回滾並指出未套用任何變更。
- 刪除系列：顯示會刪除的版本與冊數並要求確認。
- 還原失敗：不替換目前資料，提供可理解的錯誤與記錄位置。

## 13. 安全與隱私

- Tauri capabilities 採最小權限。
- 正式設定內容安全政策，不使用 `csp: null`。
- 外部文字視為不可信輸入，清理 HTML 後才顯示。
- 遠端封面限制 HTTPS、允許的 MIME、像素、檔案大小與重新導向次數。
- 自訂封面複製到應用程式資料目錄並使用安全檔名。
- API 私密金鑰、更新私鑰與未來付款憑證不得放入前端 bundle。
- 核心收藏功能完全離線可用；網路只用於 metadata 與封面查找。

## 14. 效能目標

- 正式版本在目標桌機一般情況下 2 秒內出現可操作畫面。
- 一般畫面與轉場目標穩定 60 FPS。
- 網路、封面、備份與磁碟工作不得阻塞 UI 執行緒。
- 100 本以內不預先加入清單虛擬化；元件介面保留日後替換能力。
- 封面產生適合格狀檢視的本機縮圖，避免反覆解碼原始大圖。

## 15. 測試策略

### 15.1 單元測試

- ISBN-10／ISBN-13 正規化及校驗。
- `1`、`1.5`、`10`、`上`、`下`、`全一冊`等冊別排序。
- 缺卷、收藏完成度及閱讀完成度計算。
- 擁有、已讀、想買狀態規則。
- 外部 metadata 正規化與錯誤分類。

### 15.2 資料庫整合測試

- migration 從空資料庫與舊 schema 升級。
- foreign keys 與 ISBN 唯一約束。
- 批次 transaction 全成或全敗。
- 關閉並重開後資料保留。
- 備份匯出與還原 round trip。

### 15.3 UI 測試

- 作品搜尋與批次勾選。
- ISBN 成功、無結果、限流、離線與重複結果。
- 手動新增與修正。
- 搜尋、篩選、版本切換與批次模式。
- 缺封面、空書庫、保存中、保存成功與保存失敗。
- 鍵盤快捷鍵與焦點順序。

### 15.4 Windows 正式版測試

- 安裝、啟動、關閉、再次開啟與解除安裝。
- 目標解析度與 Windows 縮放比例。
- 正式 build 啟動時間與互動流暢度。
- 實際檔案匯出、還原及資料保留。
- 一般鍵盤輸入及 USB 條碼掃描器文字輸入。

## 16. 初版最低驗收

1. 建立一個 10 冊作品並批次標記第 1–6 冊已擁有。
2. 將第 1–10 冊標記為已發行後，正確顯示缺少第 7–10 冊；即將出版或發行狀態不明的冊別不列入缺少。
3. 將第 7 冊加入想買，再轉為已擁有。
4. 擁有與已讀分開記錄，且取消擁有不清除已讀。
5. 以 ISBN 新增一冊並阻止相同 ISBN 重複加入。
6. Google Books 限流及 Open Library 無結果時仍能手動完成。
7. 正確處理 `1.5`、`上`、`下`及`全一冊`。
8. 同一作品的普通版與完全版卷數不混合。
9. 保存及修改購入價格、日期、書況與位置。
10. 關閉並重開後資料完整保留。
11. 匯出備份、修改資料、還原後回到匯出狀態。
12. 封面失敗時仍可正常瀏覽及操作。
13. Windows 正式安裝版能啟動、保存資料並正常解除安裝。

## 17. 研究結論與風險

- 官方 `create-tauri-app` 仍提供 `react-ts`，不需要為追求新模板更換已驗證技術棧。
- 第三方全配模板常加入目前不需要的 UI、路由與狀態管理依賴，且不解決漫畫資料模型，因此不採用。
- Google Books 可提供一般書目欄位，但已在真實台灣漫畫 ISBN 測試中遇到 HTTP 429。
- Open Library 對測試 ISBN `9789572690017` 沒有結果。
- 國家圖書館官方月度資料具潛力，但必須處理月度分片、實體／電子版區分、歷史資料完整性與更新流程。
- 因資料來源覆蓋率不足，完整手動流程與可替換 provider 不是備用設計，而是必要架構。
